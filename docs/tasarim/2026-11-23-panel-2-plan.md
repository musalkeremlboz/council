# Panel, second round: live flow, sessions, settings — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the panel's travelling dot show real events as they happen, keep the selection on the newest event unless the owner reads an older one, group today's events by session behind large click targets, and add a Settings section with theme choice, password change and "close other sessions".

**Architecture:** The panel stays a separate read-only process (`council/panel/`, Starlette, plain HTML/CSS/JS, no build step). A new light `pulse` answer carries events newer than a time mark; the schema page asks for it every 2 seconds. `today` gains sessions. Settings adds two POST endpoints on the gate. The only new write is `owner.json`, and only on a password change.

**Tech Stack:** Python 3.12, Starlette, SQLite, pytest; browser side plain ES5-style JavaScript as in the existing files, Web Animations API; node (optional) for `tests/js`.

**Spec:** `docs/tasarim/2026-11-22-panel.md`, section "Ek: sahibin panele baktıktan sonraki istekleri (2026-11-23)" (binding), on top of the rest of that document.

## Global Constraints

- The panel never shows or returns note text, section headings, message text, search words, rule text, commit messages or check-question text. Only note paths, counts, character totals, times and session ids leave `views.py`. Every new answer is added to the leak test (`tests/test_panel_leak.py`).
- Reading the memory stays read-only (`Store(frozen=True)`, read-only SQLite). The panel writes `panel.sqlite3` and nothing else, with one exception: `owner.json` on a password change. Every GET answer still leaves the data folder byte-identical apart from `panel.sqlite3`.
- `Content-Security-Policy: default-src 'self'`. No inline `<script>` or `<style>`, no `style=""` attributes in HTML, no `innerHTML`, `outerHTML`, `document.write`, `eval`; styles set from scripts go through CSSOM (`element.style.x = …`) or the Web Animations API. Nothing is loaded from another host.
- Every word the owner reads lives in `council/panel/text_tr.py` (Turkish); scripts contain no Turkish letters (`tests/test_panel_static.py` enforces it). Code, comments and commit messages are English.
- No new dependencies, Python or JavaScript.
- COUNCIL design system: colours only through the CSS tokens in `panel.css`; the accent (`--vurgu`) marks only the memory itself, the selected or focused item and the travelling dot; 12px card corners; no shadows, no gradients; Council Halka for capitals at 24px and above, DM Sans for text, DM Mono for paths, numbers and times.
- Anything that opens on a click (confirmation, choice, expanding list) is drawn with the panel's own elements. No `alert`, `confirm`, `prompt`, no native `<select>` dropdown, no `<dialog>` default styling.
- Motion is smooth: no element jumps from one place to another, no transition is cut half way. With `prefers-reduced-motion: reduce` continuous motion starts off and expanding lists open without a transition.
- Click targets are at least 44px high. The page works at 390px width without sideways overflow (lanes may scroll inside their own box). Keyboard: every control is reachable and shows the focus ring.
- TDD: a failing test first, then the code. `python -m pytest -q` passes whole at the end of every task (347 passed + 1 xfailed before this plan; node tests run when node 18+ is installed).
- Commit on the current branch (`panel-2`) with a plain English message; no attribution trailer. Do not push.

## Review Focus

- Two events with the same second and kind: the page must not drop or double one (keys, merging pulse answers into the list).
- A pulse request with a missing, non-numeric, negative, NaN or future `since`: answers 200 with no events (or 400), never 500, never the whole log.
- An event whose path has one block only, or blocks in two lanes: the dot's journey has no zero-length or backwards hop and never appears at the top-left corner.
- A session with a single event, an event with no session id, and a day with forty sessions: the list stays usable and the strip does not overflow.
- A password change with the wrong current password five times locks sign-in like five wrong sign-ins; a change never leaves `owner.json` half written; the new password is never logged or echoed.

**Interfaces:**
- Produces: `reader.events(...)` rows gain `"session"` (the id as stored, at most 16 characters, `""` when none).
- Produces: `views.pulse(data_dir, now: dt.datetime, since: float | None) -> {"mark": float, "events": [event, ...]}`. `event` has exactly the shape of an entry of `views.schema(...)["events"]`. Events are those (usage events and note changes) with `ts > since`, newest first, at most `EVENT_COUNT`. `mark` is the newest event time known (the newest returned event's `ts`, else `since`, else the newest event in the memory, else `0.0`). `since=None` returns no events and the mark only. Counting rules of `today` do not change.

### Task 2: The schema page shows events as they happen

**Files:**

**Interfaces:**

- Produces (pure, exported for the node test the way the existing pure helpers are): `mergeEvents(list, fresh, limit) -> list` (newest first, no duplicates by event key, capped); `nextSelection(selectedKey, oldTopKey, newTopKey) -> key` (returns `newTopKey` when `selectedKey === oldTopKey` or nothing was selected, else `selectedKey`); `journey(points, speed) -> [{x, y, offset}]` keyframes for a dot through the centres of the path's places in order, with offsets proportional to distance, no zero-length hop.

**Behaviour:**
- While the schema section is shown and the tab is visible, the page asks for the pulse every 2 seconds (`since` = last mark; the first mark comes from a pulse call without `since`). The 5-second refresh of the whole section stays for the status strip and the numbers.
- New events are merged at the top of the list (cap 30) and each plays one dot: it appears at the first block of the event's path (150 ms fade-in), travels through the path's blocks in order to the last place (the memory ring when the path ends in `haf`) at a constant speed (about 260 px/s, at least 450 ms per hop), fades out over the last 200 ms and is removed. It never loops and never jumps. At most three dots run at once; further events wait their turn (300 ms apart). The dot is one absolutely positioned element inside the lanes box, moved with the Web Animations API on `transform`; positions are measured from the blocks at the moment it starts. If the lanes box is scrolled sideways the dot stays on its blocks.
- The old per-line looping dot (`.nokta.akar`, `@keyframes akis`) is removed. The blocks and lines of the selected event's path stay drawn in ink as before.
- Clicking an event in the list selects it and plays its dot once. The "Akan nokta" switch stays: off means no dot is ever drawn. With reduced motion it starts off.
- Selection: when new events arrive and the selected event was the newest, the newest of the new ones becomes selected and is kept in sight in the list. When an older event is selected, the selection does not change and the list does not scroll. The 4-second stepping (`STEP_EVERY`, `step`) is removed. The existing switch keeps its two labels: "Canlı izleme açık" while the selection follows the newest; "Canlı izlemeyi sürdür" while an older event is selected, and clicking it selects the newest and resumes following. Selecting a block (block mode) also stops following.
- No dot is drawn for events that were already in the list when the page was opened.

### Task 5: Changing the password and closing other sessions

**Files:**
- Modify: `council/oauth.py` (new `write_owner`), `council/cli.py` (uses it), `council/panel/gate.py`, `council/panel/app.py`, `council/panel/views.py` or `app.py` (settings answer), `council/panel/static/settings.js`, `panel.css`, `council/panel/text_tr.py`, `docs/kurulum.md`, `docs/setup.md`
- Test: `tests/test_panel_gate.py`, `tests/test_panel_door.py`, `tests/test_panel_frozen.py` (or wherever "writes nothing" is asserted), `tests/test_panel_leak.py`

**Interfaces:**
- Produces: `council.oauth.write_owner(data_dir: Path, password: str) -> None` — writes `owner.json` (the `hash_password` record) to a temporary file in the same folder, `chmod 600`, `os.replace`; `council set-password` uses it. `MIN_PASSWORD = 10` lives beside it and the CLI uses it.
- Produces: `Gate.change_password(token: str, current: str, new: str, now: float | None = None) -> str` returning `"ok"`, `"signed_out"`, `"locked"`, `"wrong"` (the current password did not match; counted as a failed sign-in), `"weak"` (shorter than `MIN_PASSWORD` or longer than 200 characters) or `"same"`. On `"ok"` the owner record is rewritten with `write_owner` and every session except `token`'s is deleted. Order of checks: session, lock, strength of the new one, current, same.
- Produces: `Gate.sign_out_others(token: str) -> int` (sessions closed) and `Gate.session_info(token: str, now=None) -> {"sessions": int, "expires": float} | None`.
- Produces: `POST {base}/api/password` with JSON `{"current": str, "new": str}` → 200 `{"ok": true, "closed": n}`; 401 `{"error": "signed_out"}`; 403 `{"error": "wrong"}`; 400 `{"error": "weak" | "same" | "bad_request"}`; 429 `{"error": "locked"}`. `POST {base}/api/sessions/close-others` → 200 `{"closed": n}`. Both require an `Origin` header that matches `Host` (a POST without `Origin` is refused with 403 on these two routes). `GET {base}/api/settings` → `{"sessions": n, "expires": ts, "min_length": 10}`.
- The password is never logged, never put in an exception message, never echoed in an answer.

**Behaviour (Settings page):**
- Card "Şifre": three password fields (current, new, repeat; `autocomplete="current-password"` / `"new-password"`), a line saying the minimum length and that the same password is asked when a Claude app is connected to the memory; the submit button is enabled when the new one is long enough and both new fields match; answers are shown as a line under the form in the panel's own type (no alert): success (with how many other sessions were closed), wrong current password, too short, same as the old one, locked. On success the fields are cleared.
- Card "Oturumlar": how many sessions are open and when this one ends; a button "Diğer oturumları kapat" that asks once in place (the button turns into "Emin misin? Kapat" / "Vazgeç") and then reports how many were closed.
- Docs: the Panel sections of `docs/kurulum.md` and `docs/setup.md` say that the panel can change the owner password, what else that password is used for, and that this is the only thing it writes besides `panel.sqlite3`.
