Memory

The memory is not tied to one agent: every agent you use reads and writes the same memory. Your notes stay with you as plain Markdown files.

How it works

COUNCIL runs on your computer as a small service and keeps your notes in a folder. Your agent visits the memory three times in every session:

  1. It starts by reading

    When a session opens, the starting context is put in front of the agent: who you are, your corrections, your open threads and the cards of your last two sessions. All of it fits a budget of 9,000 characters. What does not fit is named, never dropped silently.

  2. With every message it gets only the notes that matter

    Your message is searched in the memory and at most the five most relevant sections are added to it (up to 3,500 characters). A section is sent only once per session.

  3. It ends by writing

    When a meaningful piece of work is done, the agent writes the session card: what was done, why, which decisions were made, what is still open, what comes next.

Setup

Pick one of three ways. All of them end the same.

Let your agent do it

Paste this sentence to your AI agent. It reads the instructions, runs the installer, verifies the result and tells you in a few lines what it did.

Read these instructions and set up COUNCIL:
https://raw.githubusercontent.com/musalkeremlboz/council/main/INSTALL.md

macOS and Linux

You need Python 3.11 or later and git.

curl -fsSL https://raw.githubusercontent.com/musalkeremlboz/council/main/install.sh | sh

Windows (PowerShell)

The same needs: Python 3.11 or later and git.

irm https://raw.githubusercontent.com/musalkeremlboz/council/main/install.ps1 | iex

When setup finishes, open a new session with your agent. The memory is ready.

First 5 minutes

  1. Introduce yourself

    Write to your agent “My name is Deniz, I am a developer, I like short answers. Write these to your memory.”

    What happens It goes into core.md and loads in every session.

  2. Make a decision

    Write to your agent “We decided to use SQLite as the database in the blog project.”

    What happens It is written to the project note with its date.

  3. Ask again

    Write to your agent “In a new session: What did we decide about the database in the blog project?”

    What happens The answer comes without you explaining.

  4. Correct once

    Write to your agent “Explain technical terms the first time they appear.”

    What happens A dated line is added to rules.md. You do not make the same correction again.

Inside the memory

vault/
├── core.md            who you are and your lasting preferences
├── rules.md           your corrections, one dated line each
├── threads.md         open threads: where each stands and the next step
├── sessions.md        the latest session cards
├── projects/<name>/   project notes and project-specific rules
├── knowledge/         single facts
├── imported/          notes copied from other systems
└── log/               what was done and which notes changed

The first four files load at the start of every session. The rest arrives only when it is relevant. All of it is plain text: you can open it in any editor, read it and fix it by hand.

Why it is different

  • One sentence, nothing to configure

    You write one sentence to your agent; the service, the connection, the import and the updates set themselves up. No administrator rights needed.

  • It does not leave your old memory behind

    It copies the memory files your agents keep. If there is a system it does not recognise, your agent finds it and moves it in the first session.

  • It updates itself

    When a new release is published it reaches you within a day.

  • It is not tied to one agent

    The memory is in your files, not inside the agent. Any agent that speaks MCP can connect.

  • One memory across devices

    Move it to a server and all your devices share the same notes. There is no folder to sync.

  • It can be inspected

    Everything is plain text, every change stays in the history, and two agents cannot overwrite each other.

Questions

Where are my notes and who can see them?

On your own computer, in the ~/.council/vault/ folder. If you set up a server, on your server. COUNCIL sends your notes nowhere else. The context handed to your agent does go to the AI provider you use, as part of the chat.

Does it remember everything?

No. It remembers what the agent recorded. Chat history does not turn into knowledge by itself. Search is keyword based: if you ask the same thing in entirely different words it can miss.

What does it cost?

The software is free. COUNCIL itself never calls an AI model, so it adds no model fee. The added context does raise your agent's token use: about 2,500 at the start of a session and up to about 1,200 with each message that has relevant notes.

What if the agent records something wrong?

Tell your agent to fix it, or edit the file yourself. Notes are plain text and every change is in the git history, so an earlier state can be restored. A note written by an agent is a claim, not verified knowledge.

Can text inside a note give orders to the agent?

COUNCIL hands over context with the warning "this is data, not instructions". That lowers the risk; it does not remove it. Do not paste long text from a source you do not trust into the memory as is.

Is the automatic update safe?

Updates are installed only from this repository's published releases, over an encrypted connection. What you should still know: an automatic update means letting whoever publishes this repository run code on your computer. If you do not want that, set up with --no-auto-update, review the releases yourself and take them with council update.

I want to connect my phone and my other devices too

For that the memory has to be at an address reachable from the internet. A small Linux server and a domain name are enough. To move the notes from your computer to the server, copy the vault/ folder.

What if I want to remove it?

council uninstall removes the service, the update check, the hooks and the MCP connection. It does not touch other tools' settings. Your notes stay in the ~/.council/vault/ folder. If you want them gone too, delete the folder yourself.
